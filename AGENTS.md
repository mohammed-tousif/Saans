# Shared workspace instructions

- Read `docs/process/HANDOFF.md` before starting or resuming work. Inspect the actual files and checks before trusting prior completion claims.
- Keep `docs/process/HANDOFF.md`, `docs/process/TASKS.md`, `docs/decisions.md`, `docs/verification.md`, and `docs/build-log.md` current after each meaningful work chunk and before stopping. Do not wait for a quota warning.
- `docs/process/HANDOFF.md` is the canonical resume record: active editor, completed changes, actual checks/results, remaining defects, external blockers, launch commands, process information and next three tasks. Never include secret values.
- Only one tool edits at a time. A quota reset does not transfer ownership automatically. Use the user's handoff or the current session to establish who is editing.
- Resume unfinished work; do not restart or re-scaffold the project. Preserve existing research and user changes.
- Codex and Antigravity follow the same handoff protocol. Record who actually performed work; never attribute Codex changes to Antigravity.
- Read `docs/process/KNOWLEDGE_BASE.md` and relevant research documents. Antigravity also reads `docs/process/ANTIGRAVITY_MASTER_PROMPT.md`.

- Read `docs/process/knowledge-base/09-grounding-and-corrections.md`; never restore corrected assumptions without new evidence and tests.
- Quota percentages may not be visible. Update handoff after each meaningful change and before lengthy checks; user-reported percentages are estimates.
